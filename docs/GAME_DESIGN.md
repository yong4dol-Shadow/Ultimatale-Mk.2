# Shadow the Hedgehog — 16-bit / Undertale × Deltarune 리메이크 기획서

> 2005년작 《Shadow the Hedgehog》의 세계관·스토리·캐릭터·제목을 그대로 가져오되,
> 그래픽은 16비트 픽셀 아트, 시스템은 《언더테일》 + 《델타룬》 결합형으로 재구성한다.

---

## 1. 기본 사양

| 항목 | 내용 |
|---|---|
| 제목 | Shadow the Hedgehog |
| 플랫폼 | HTML5 / Canvas 2D / 순수 JavaScript (빌드 툴 없음) |
| 내부 해상도 | 320 × 240, 정수배 확대 + nearest-neighbour |
| 텍스트 | 별도 고해상도 레이어 (디스플레이 실제 픽셀 밀도) |
| 그래픽 | 16비트 사이드뷰 픽셀 아트 (전부 코드로 생성, `tools/`) |
| 사운드 | WebAudio 칩튠 트래커 (펄스 / 삼각파 / 노이즈 3~4채널) |
| 저장 | localStorage 1슬롯 (`shadow_the_hedgehog_16bit_v1`) |
| 언어 | 한국어 |

조작: 방향키·WASD 이동 / **Z·Enter** 확인 / **X** 취소·대시 / **C** 메뉴·설정 / F 전체화면 / M 음소거

설정(타이틀 `OPTIONS`, 게임 중 `C` → SETTING)은 세이브와 별도 키에 저장된다.

| 항목 | 값 | 효과 |
|---|---|---|
| 이동 속도 | 보통 / 빠름 / 매우 빠름 | 배율 ×1.0 / ×1.35 / ×1.75 |
| 항상 대시 | 꺼짐 / 켜짐 | 켜면 X 없이 대시 속도, X 는 정밀 이동으로 반전 |
| 텍스트 속도 | 보통 / 빠름 / 즉시 | 42 / 75 / 즉시 (초당 글자 수) |
| 튜토리얼 | 켜짐 / 꺼짐 (+초기화) | 상황별 한 줄 안내, 각각 1회만 |

기본 이동 속도는 걷기 106 px/s, 대시 176 px/s.

## 2. 게임 루프

```
타이틀 → 프롤로그 → [오버월드 ↔ 랜덤 인카운터 전투] × 5 스테이지 → 피날레 → 엔딩
                                                              ↳ ENDING 3 클리어 시 LAST STORY 해금
```

## 3. 오버월드 (`overworld.js`)

* 16×16 타일, 맵 크기 **208×144 타일(3328×2304px)** — 가로 10.4화면, 세로 9.6화면.
  스핀 대시가 의미를 가지려면 2초 만에 벽에 닿지 않는 직선이 필요하다.
  카메라가 섀도우를 추적한다.
  맵은 `tools/gen_maps.py` 가 생성하며, 스폰에서 모든 오브젝트와 게이트까지의
  도달 가능성을 플러드 필로 검증한다.
* 섀도우는 **오버월드 전용 34×30 스프라이트**로 자유 이동한다.
  (40×44 전투 스프라이트는 16px 타일 기준 거의 세 칸 높이라 맵에 쓰지 않는다.)
  **옆·앞·뒤 세 방향**을 입력에 맞춰 전환하며, 대시 중에는 **호버 스케이트 자세**로 바뀐다.
  스케이트 사이클은 걷기보다 **느리게**(초당 4.2프레임 ≈ 1주기) 돌린다 — 대시 속도에
  맞춰 초당 3주기를 돌렸더니 발만 동동거려서 전력 질주로 보였다. 이동 속도는 다리가
  아니라 활주에서 나와야 한다.
* **가속** — 시리즈처럼 최고 속도까지 **점점 붙는다**(가속 200 px/s² ·
  감속 620 px/s²). 키를 놓으면 훨씬 빠르게 멎어서 조작감은 유지된다.
* **에어 슈즈의 3단계 점화** — 불은 속도가 아니라 **점화 타이머**(burn)로 단계가
  올라간다. 가속 자체가 1초 남짓이라, 속도로 단계를 나누면 중간 단계가 0.3초쯤
  스쳐 지나가 아예 보이지 않았다. burn 은 스케이트 중 속도에 비례해 차오르며,
  0.35 에서 **뒤꿈치 분사**, 1.35 에서 **전체 화염** — 중간 단계가 약 **1초**
  유지된다.
* **단계가 곧 최고 속도다** — 불은 장식이 아니라 지금 얼마나 빠른지를 읽는
  계기판이다. 걷기 106 · **차가운 스케이트 130 · 뒤꿈치 180 · 완전 점화 248** px/s.
  간격을 30~40%씩 벌려놔서 스톱워치가 아니라 손끝으로 구분된다.
  burn 충전량은 **지금 있는 단계의 최고 속도** 기준으로 계산한다 — 최상위 단계
  기준으로 재면 완전 점화를 빠르게 만들수록 중간 단계가 늘어져서, 1초 유지가
  깨진다.
* **멈추면 즉시 꺼진다** — 감쇠 2.5/s 에 더해, **속도가 0이 되는 순간 burn 도 0**.
  감쇠만으로는 멈췄다가 반 초 안에 다시 출발했을 때 불씨가 남아 있었는데, 그게
  바로 처음부터 다시 올라가야 하는 경우다. 다시 달리면 **불없음 → 뒤꿈치 →
  완전 점화**를 바닥부터 다시 밟는다 — 그 상승이 이 이동의 재미 전부라서,
  한 번 점화했다고 유지시켜 주면 그 재미가 게임 통틀어 한 번만 발생한다.
* **스핀** — 완전 점화 상태로 달리는 중, **좌우 키를 누르고 있는 상태에서 ↓** 를
  누르면 0.62초간 몸을 말아 구른다. 좌우가 눌려 있지 않으면 — 즉 **멈춰 있으면 ↓ 는
  아무 일도 하지 않는다**. ↓ 만으로 발동시켰더니 아래로 걷고 싶을 때마다 몸을 말아
  버렸다. 제자리에서의 스핀은 스핀 대시 쪽이 담당한다.
  속도 **1.45배**(완전 점화 248 기준 약 360 px/s), 구르는 동안 **랜덤 인카운터가
  누적되지 않는다**. 이미 향하던 방향을 그대로 유지하므로 방향키와 싸우지 않는다.
* **스핀 대시** — 제자리에서 **↓ 를 누른 채 Z 또는 X 를 연타**한다. 한 번 칠 때마다
  한 바퀴 감기고(최대 6), **↓ 를 떼면 발사**된다. 6바퀴면 정지 상태에서 곧바로
  최고 속도로 튀어나가고, 구르는 동안 **가던 방향의 키를 누르면 몸을 풀고** 그대로
  스케이트로 이어진다. 나올 때는 이미 완전 점화 상태다.
  **게임에서 제일 빠른 수단이어야 한다** — 정지 상태와 1초의 연타를 지불하는
  기술이니, 그냥 방향키를 누르고 있는 것보다도, 달리다 구르는 스핀보다도 빨라야
  쓸 이유가 생긴다. 그래서 발사 배율이 감은 횟수에 따라 1.45 → **1.85** 로 올라가고
  (6바퀴에 **약 460 px/s**, 완전 점화 주행의 1.85배 · 러닝 스핀의 1.3배),
  지속도 1.09초로 더 길다.
  몸을 푸는 조건은 방향키를 **새로 누르는 것**이지 누르고 있는 상태가 아니다 — 축을
  그대로 읽으면 달리던 방향은 이미 눌려 있으니 구르기 시작한 다음 프레임에 곧바로
  풀려 버려서, 달리던 중의 스핀이 한 프레임 만에 끝났다.
  스탠스는 **↓ 만으로는 들어가지 않고 첫 타격에서** 시작한다 — ↓ 는 원래 아래로
  걷는 키이고, 그게 그 키가 하는 일의 대부분이기 때문이다. 연타에 쓴 Z 는 조사에
  쓰이지 않는다.
* **멈추면 불은 완전히 꺼진다** — 감쇠 2.5/s 로 burn 이 0 까지 떨어진다. 다시
  달리면 **불없음 → 뒤꿈치 → 완전 점화**를 처음부터 다시 올린다. 점화를 유지해
  두면 그 상승이 게임 통틀어 한 번밖에 일어나지 않고, 그 상승이 이 이동의 재미
  전부다. 대신 올라가는 쪽은 넉넉히 잡았다 — 두 임계값의 간격이 1.0 burn 이라
  뒤꿈치 단계가 **약 1초** 유지된다.
* **지형 읽기** — 달릴 수 있는 바닥과 벽의 경계에 **전부 테두리를 그린다**: 벽 위쪽
  모서리에 밝은 캡, 바닥 쪽으로 떨어지는 그림자, 좌우 면에도 같은 처리. 스테이지마다
  팔레트가 달라 어떤 벽은 어떤 바닥보다 밝았기 때문에, 그림만 보고는 어디가 길인지
  추측해야 했다.
* **표지판 · 사람 · 데이터 로그** (`B` / `N` / `L`) — 미션과 무관하게 **몇 번이든
  읽을 수 있는** 오브젝트.
  스테이지마다 **표지판 6 · 사람 4~5 · 데이터 로그 3~4**, 합쳐서 13~15개가 흩어져
  있고 전부 서로 다른 내용이다(인덱스가 순환하지 않도록 텍스트 수를 오브젝트 수에
  맞춰 두었다). 2005년 원작의 줄거리를 미션 사이사이에 풀어놓는다 — 웨스토폴리스의
  대피 안내와 시민들과 G.U.N. 교신 기록, 협곡의 해독판과 조사대 음성 메모, ARK 의
  프로젝트 경과 보고와 마리아의 의무 기록과 봉쇄 당일 통신, 요새의 위령비와 폐기
  보류 회람, 혜성의 신경 조직에 새겨진 계약. 맵이 넓어도 걸어다니는 것 말고 할 게
  없으면 그건 그냥 빈 땅이다.
* **배치물** (`D`) — 가로등 · 소화전 · 벤치 · 자판기 · 부서진 차 · 드럼통 ·
  바리케이드 · 공중전화 · 동상 · 오벨리스크 · 돌무지 · 고사목 · 화로 · 유해 ·
  카오스 결정 · 콘솔 · 배양 탱크 · 로커 · 안테나 · 발전기 · 레이더 · 탄약상자 ·
  자동 포탑 · 살덩이 · 신경절 · 알집 — **26종**을 스테이지별 팔레트로 나눠
  **한 스테이지에 320~360개**(화면당 서너 개) 뿌린다. **전부 통과 가능**하다.
  타일만 깔린 화면이 몇 개씩 이어지면 맵이 아무리 넓어도 반복으로 읽힌다.
  팔레트 인덱스는 순서가 아니라 **타일 좌표를 섞어** 고른다(순서대로 고르면 몇 줄
  떨어진 배치물끼리 같은 슬롯에 걸려 같은 가로등이 나란히 보인다).
* **배치물 조사** (`SH.PropLore` / `Overworld.examineProp`) — 배치물은 눈요기가
  아니라 **전부 Z 로 조사된다**. 종류마다 관찰 문장이 두세 개씩 있고, 어느 문장이
  나올지는 **타일 좌표 해시**로 고정된다 — 같은 가로등은 늘 같은 말을 하고, 옆
  가로등은 다른 말을 한다. 두 번째 누르면 `again` 문장으로 넘어가 같은 줄을
  반복하지 않는다. 답은 대화 상자가 아니라 **화면 상단 알림(`notice`)**으로 뜬다:
  달리다 스치듯 눌러도 흐름이 끊기지 않아야 하기 때문이다. 누른 배치물은 살짝
  튀어올라 반응한 것이 보인다.
  * **뒤지면 나오는 것** — 자판기 · 잔해 · 드럼통 · 로커 · 배양 탱크 · 탄약상자 ·
    돌무지 · 고사목 · 카오스 결정 · 신경절 · 알집 · 살덩이에는 `loot` 가 걸려
    있지만, **좌표 해시가 `odds` 에 걸린 것만** 실제로 물건을 갖고 있다(스테이지당
    20~30개, 전체의 6~9%). 전부 나오면 회수 아이템 자체가 무의미해진다. 한 번
    나오면 끝이고, 가방(8칸)이 차 있으면 그대로 남는다.
  * **벤치** — 해시에 걸린 벤치(스테이지당 8~17개)는 **한 번만** 앉을 수 있고
    HP 를 20 돌려준다. 체력이 가득이면 앉지 않는다(낭비되지 않게).
  * **화로** — 협곡의 꺼진 화로는 카오스 에너지를 흘려넣어 **불을 붙일 수 있고,
    붙인 불은 꺼지지 않는다**(`fx_flare` 가 화로 위에 얹힌다). 지나온 길을
    되짚어볼 수 있는 표식이 된다.
  * **공중전화** — 처음 누르면 끊기는 통화가 한 줄 재생된다(`pickup`).
  배치물은 **미션 목표가 아니다**. 목표 오브젝트가 사정거리에 함께 들어오면
  프롬프트는 **항상 목표 쪽이 가져간다** — 한 스테이지에 300개가 넘게 깔려 있어서,
  가로등이 단말의 Z 를 가로채면 그것만으로 스테이지가 망가진다.
* **미션 오브젝트는 눈에 띄게 크다** (`objectives` 시트 · 24×36) — 단말 · G.U.N.
  컨테이너 · 산란낭 · 카오스 에메랄드는 원래 16×16 타일로 바닥에 납작하게 깔려
  있었다. 한 화면에 배치물이 서너 개씩 깔린 상태에서 **배치물과 정확히 같은 크기**
  였으니, 단말을 찾으려면 가로등을 하나하나 읽어야 했다. 지금은 배치물(16×24)의
  두 배가 넘는 부피에 디테일을 넣었다 — 단말은 화면·키 선반·케이블·상태등이
  달린 콘솔(세이브 기둥의 가느다란 기둥 실루엣과 헷갈리지 않게 낮고 넓다),
  컨테이너는 팔레트 위에 얹힌 교차 보강대 + 경고 띠 + 스텐실 명판, 산란낭은
  뿌리와 혈관과 속에서 빛나는 core.
  **카오스 에메랄드만은 보석 자체를 키우지 않았다** — 키웠더니 HUD 아이콘과
  다른 물건처럼 보였다. 보석은 16×16 HUD 스프라이트 그대로 두고, 대신 **단상**
  위에 얹었다: 두 단 계단 + 홈 판 기둥 + 소켓에서 타오르는 빛 + 양옆으로 흩날리는
  입자. 멀리서 찾게 만드는 건 보석이 아니라 그걸 받치고 있는 물건이다.
  **가져간 뒤에도 단상은 남는다** — 불 꺼진 소켓에 죽은 색으로. 이미 훑은 구역이
  훑은 것처럼 보여야 한다.
  * **공통 마커** — 실루엣만으로는 부족해서, **아직 남은 목표는 전부 같은 다이아
    마커**를 머리 위에 띄운다(2프레임으로 위아래로 뜬다. G.U.N. 계열은 노랑,
    블랙 암즈 계열은 초록). 화면을 훑어서 목표를 찾을 수 있다는 뜻이다.
  * **끝낸 목표는 마커를 뗀다** — 작동시킨 단말은 마커 없는 프레임으로 바뀌고
    화면이 켜진다. 남은 것과 끝낸 것이 맵만 봐도 구분된다.
  * 드롭 섀도와 Z 프롬프트 높이도 이 크기에 맞춰 따로 잡는다.
* **넓고 트인 지형** — 스테이지는 **208×144**(약 10화면 × 9화면). 스핀 대시가
  의미를 가지려면 2초 만에 벽에 닿지 않는 직선이 필요하다. 그래서 도시 블록은
  셋 중 하나를 통째로 비워 광장을 만들고, 협곡 기둥은 수를 줄여 시야만 끊게 하고,
  요새의 방들은 간격을 넓혔다. 장애물은 **경로가 아니라 시야를 막는** 쪽이다.
* **랜덤 인카운터**: 이동 거리가 누적되어 임계값을 넘으면 전투 발생.
  임계값은 매번 다시 굴리며, **폭이 아주 넓다(레이트의 0.8배 ~ 3.2배)** — 언더테일이
  그렇듯 짧게 두 번 연달아 붙기도 하고 한참 조용하기도 해야 한다. 좁은 폭으로 굴리면
  다음 전투까지 초를 셀 수 있을 만큼 기계적으로 느껴진다.
  기본 속도로 계속 달릴 때 **약 10초 ~ 37초(평균 23초)** 간격이다.
  누적 거리는 **이동 속도 설정으로 나눠서** 센다 — '매우 빠름'은 한 번의 인카운터
  사이에 맵을 더 넓게 도는 것이지, 전투를 더 자주 만나라는 설정이 아니다.
  스테이지별 인카운터 레이트와 조우 테이블이 따로 있고, 맵 진입 직후(500)와
  전투 직후(700)에는 유예 거리를 준다.
* **상호작용 오브젝트**: 단말(터미널), G.U.N. 보급 컨테이너, 블랙 암즈 산란낭,
  카오스 에메랄드, 구역 게이트.
* **HUD**: 좌상단 3종 미션 진행판, 하단 HP / 링 / 에메랄드 7개 슬롯.

### 3.1 미션 락 (원작 계승)

원작처럼 **한 스테이지에 세 개의 목표가 동시에 존재**하고, 셋 중 **아무거나 하나**를
달성하면 다음 구역으로 가는 게이트의 봉쇄가 풀린다.
가장 먼저 달성한 목표가 그 스테이지의 "선택"으로 기록된다.

## 4. 전투 (`combat.js`)

### 4.1 구도 — 델타룬식 사이드뷰

정면 뷰(언더테일)가 아니라 **양옆 대치**다.
섀도우는 화면 왼쪽에서 오른쪽을 보고, 적 1~3체는 오른쪽에서 왼쪽을 본다(스프라이트 좌우 반전).
바닥선 y=124. 비행 유닛(비틀·호크·둠)은 `hover` 값만큼 떠 있고 지면에 그림자를 드리운다.

화면 배치
```
 y  0.. 16  상태바 (이름 / LV / HP 게이지 / TP 게이지)
 y 18..126  전투 필드 — 섀도우(좌) vs 적(우)
 y130..212  서브 영역: 메시지 · ACT/ITEM/대상 목록 · 공격 타이밍 바 · 탄막 박스
 y216..238  FIGHT / ACT / ITEM / MERCY 버튼 열
```

### 4.2 플레이어 턴

* **FIGHT** — 대상 선택 후 **언더테일식 한 방향 타이밍 바**(커서가 한 번만 통과).
  중앙에 가까울수록 `MISS → GOOD(×1.1) → GREAT(×1.45) → PERFECT(×1.95)`.
  PERFECT 도 카오스 스피어보다는 **아래**에 둔다 — 사격은 공짜로 반복할 수 있으니,
  스피어와 비슷한 값이 나오면 TP 게이지가 팔 게 없어진다.
  결정하면 섀도우가 **사이드암을 발사**한다: 사격 포즈 → 총구 화염 → 짧은 예광탄 →
  **명중 지점의 초소형 폭발**(불꽃 튐 → 화염구 → 잔불, 3프레임) 순으로 이어진다.
  카오스 계열의 에너지 타격만 긴 섬광 이펙트를 쓰고, 총알은 이 작은 폭발을 쓴다.
* **ACT** — 적별 고유 행동. 각각 자비(mercy) 수치를 ±로 움직이고, 일부는 적의 AT/DF를 바꾼다.
  ACT 목록에는 TP를 쓰는 두 기술이 함께 나온다.
  * 셋 다 **카오스 에메랄드를 하나라도 얻은 뒤에** 풀린다 — 에메랄드의 힘이니까.
    그 전에는 목록에 회색으로 남아 이유를 표시한다(조용히 사라지면 버그로 읽힌다).
  * **카오스 스피어** (TP 40) — 적 전체에 관통 피해 (ATK ×2.2, **적 DEF 절반만 계산**).
    ×1.5에 DEF를 전부 계산하던 시절엔 GREAT 타이밍 사격보다도 못해서 TP를 쓸 이유가
    없었다. 한 대상 기준 실측(ATK 11):

    | 대상 | GOOD | GREAT | PERFECT | 스피어 | 블래스트 |
    |---|---|---|---|---|---|
    | G.U.N. 병사 (DEF 1) | 11.1 | 14.9 | 20.4 | **23.7** | 38.5 |
    | 블랙 워리어 (DEF 2) | 10.1 | 14.0 | 19.4 | **23.2** | 38.5 |
    | 블랙 오크 (DEF 4) | 8.1 | 12.0 | 17.5 | **22.2** | 38.5 |

    PERFECT 사격보다 확실히 위이고 DEF가 높을수록 격차가 벌어지며, 게다가 전체를 친다.
    블래스트와는 여전히 차이가 크다.
  * **카오스 블래스트** (TP 100) — 적 전체에 방어 무시 대미지 (ATK ×3.5)
  * **TP** 는 0에서 시작하며 그레이즈(초당 22)와 명중(+8)으로 찬다.
    그레이즈 중에는 델타룬처럼 **하트 자신에게 흰 테두리가 켜지고** 옅은 청색
    빛이 감돈다(숫자 팝업 없음 — 눈이 이미 가 있는 곳에서 읽히게 한다).
    40 / 100 을 처음 넘길 때 게이지가 번쩍이며 튜토리얼 한 줄이 뜬다.
  * **카오스 컨트롤**(MERCY / 데빌 둠 ACT)도 연출이 붙는다 — 캐스터에서 파문이 세 겹
    퍼지고, 잔상이 옆으로 늘어지고, 화면에 균열선이 흐른 뒤에 결과가 적용된다.
  * 두 기술은 연출이 끝난 뒤에 대미지가 들어간다 — 스피어는 **황금 에너지 창**이
    대상마다 하나씩 시차를 두고 날아가고, 블래스트는 **적색 내파 후 대폭발**이
    화면을 덮은 다음 판정된다.
  * **카오스 스피어**의 창은 미늘이 달린 긴 랜스로, 흰 심지 · 금색 대 · 주황 오라
    3중에 불꽃 항적을 끌고 간다. 적에게 **꽂혀 멈추지 않고 관통해 지나가며**,
    뚫린 자리에 **금색 화염이 붙어 타오른다**(3개가 시차를 두고 타올라 흔들린다).
    에너지 창이므로 베기 이펙트를 쓰지 않는다 — 길쭉한 섬광은 검에 베인 그림이다.
* **MERCY** — SPARE / **카오스 컨트롤**(이탈). 자비 조건을 만족한 적은 이름이 **노랗게** 빛난다.

명령 버튼 네 개(FIGHT / ACT / ITEM / MERCY)는 **언더테일과 같이 평소엔 전부 주황색**이고,
커서가 올라간 하나만 **노란색**으로 바뀐다(테두리 · 아이콘 · 글자 모두). 버튼마다 다른 색을
주면 네 개가 서로 무관한 위젯처럼 읽혀서, 아이콘도 주황/노랑 2종으로 각각 뽑아 쓴다.
* **ITEM** — 링(HP), 카오스 드라이브(TP), ARK 배급식(HP).

SPARE 조건은 적마다 `{ mercy: N, hpBelow: r }` 로 정의된다 — 대화로 풀거나,
빈사까지 몰아붙여도 열린다(언더테일 규칙).

### 4.3 적 턴 — 탄막 회피

화면 중앙 하단에 200×82 박스가 열리고 붉은 **소울(하트)** 을 방향키로 조작한다.
X 홀드 시 정밀 이동(감속). 총 **19종 탄막 패턴**:

|---|---|
| G.U.N. | `gunLine` `gunSpread` `beetleLaser` `homing` `hunterMissiles` `hunterSweep` |

| 보스 | `doomEyes` `doomLaserGrid` `devilEyeBeam` `devilMeteor` `devilVortex` |

* 붉게 점멸하는 예고(`warn`) 후 발사되는 탄이 있다.
* **그레이즈**: 스치면 TP가 찬다(델타룬 규칙). 스치는 동안 하트에 흰 테두리가
  켜지고, 탄이 지나가면 몇 프레임에 걸쳐 사그라든다. 피격 시 1초 무적 + 화면 흔들림.

## 5. 분기 (`story_branch.js`)

전투와 미션의 결과가 세 개의 점수로 누적된다.

```
darkScore    = 인간처치×2 + 소닉진영처치×6 + DARK미션×12
heroScore    = 외계처치×2 + 인간자비×1     + HERO미션×12
neutralScore = 총자비×2                    + NORMAL미션×14
```

소닉 진영을 베는 것은 되돌릴 수 없는 선택이라 가중치가 가장 무겁다.

### 엔딩 판정

| 엔딩 | 조건 | 최종전 | 결말 |
|---|---|---|---|
| **1. 인류 학살** | darkScore 최대 | **소닉 + 테일즈** | 블랙 둠마저 밀어내고 우주 최강의 생명체로 군림 |
| **2. 방관자** | 총 처치 0 (순수 평화주의) 또는 최종전 회피 | 없음 (컷신) | 불개입 → 무방비 인류가 블랙 암즈에게 패배 |
| **3. 외계인 학살** | heroScore 최대 | **블랙 둠** | 영웅이 되지만 기원에 대한 찝찝함이 남음 |
| **진엔딩** | ENDING 3 을 *순수 히어로*(인간·소닉 처치 0) + **에메랄드 7개**로 클리어 | **데빌 둠** | 슈퍼 섀도우 각성, "안녕이다, 섀도우 더 헤지혹" |

최종전에서 보스를 **SPARE 하거나 도주하면** 아무도 막지 못한 것이 되어 엔딩 2로 귀결된다.

카오스 에메랄드는 5개 스테이지에 **정확히 7개** 배치되어 있어 한 회차에 전부 회수 가능하다.

## 7. 에셋 파이프라인

`assets/sprites/*.png` 와 `js/sprite_data.js` 는 **전부 `tools/` 의 파이썬 스크립트가 생성한다.**

```
tools/pixel.py    픽셀 캔버스 · 도형 래스터라이저 · 자동 외곽선 / 명암 · PNG 라이터
tools/chars.py    고슴도치 3종 (섀도우 / 슈퍼 / 소닉 / 테일즈) — 파라메트릭 포즈
tools/enemies.py  G.U.N. · 블랙 암즈 · 보스 · 마리아
tools/tiles.py    5개 존의 16×16 타일 33종
tools/ui.py       소울 · 에메랄드 7색 · 링 · 아이콘 · 탄환 · 이펙트
tools/gen_sprites.py  전부 렌더 → PNG + base64 인라인 JS
```

애니메이션 프레임은 복사·수정이 아니라 **같은 그리기 함수에 다른 관절 각도를 넣어 다시 그린 결과**다.
`python3 tools/gen_sprites.py` 한 번이면 29장의 시트가 재생성되며, 생성 직후
모든 액터 프레임이 셀 경계에 닿지 않는지(= 외곽선이 잘리지 않는지) 자동 검사한다.

두 가지는 도형으로 그리지 않는다.

* **얼굴** — 두상이 18px 남짓이라 타원은 눈을 동그라미로 뭉개고 머즐을 얼굴에 녹인다.
  눈·머즐·사람 눈은 ASCII 픽셀 맵(`EYE`, `MUZZLE`, `HUMAN_EYE`)으로 직접 찍는다.
  구성은 원본 디자인 그대로: 살색 주둥이는 두개골 실루엣 안쪽(-1px)에 머물고
  검은 코만 그 앞으로 +3px 혹처럼 나오며, 작은 타원 눈이 주둥이 위에 걸터앉고, 입은 없다.
* **가시** — 가는 선이면 바늘 다발, 밑동이 겹치면 한 덩어리 후드가 된다.
  각 가시를 `(밑동, 각도, 길이, 밑동 두께, 끝 두께)` 로 정의해 부채꼴로 펼친 사다리꼴로 그린다.

자신의 그림으로 바꾸려면 `tools/import_sheet.py` 를 쓴다(README 참조).
